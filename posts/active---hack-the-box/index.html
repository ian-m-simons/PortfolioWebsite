Overview#

This machine was discovered completely by accident. I had originally planned to complete a different box but accidentally scanned the wrong IP. After spending longer than I would care to admit attacking a web server I was convinced was an Active Directory Domain Controller, I decided to do Active instead. I am really glad I did. It helped break down the perceived complexity I had associated with Active Directory Machines, and demonstrated that successful domain compromise often results from methodical enumeration and chaining of realistic misconfigurations rather than highly complex exploitation techniques.

Attack Path Summary#

  1. Performed Network Reconnaissance with Nmap and identified exposed SMB services on the target

  2. Performed SMB enumeration and identified anonymous read access to Replication share

  3. While enumerating Replication share, identified a Group Policy Preferences (GPP) credential file Groups.xml. Said file contained a cpassword value associated with the SVC_TGS account

  4. Decrypted cpassword value and recovered the password GPPstillStandingStrong2k18

  5. Validated recovered credentials and obtained authenticated domain access as SVC_TGS

  6. Enumerated Service Principal names (SPNs) and identified a Kerberoastable SPN associated with the Administrator account

  7. Requested Ticket Granting Service (TGS) ticket for the Administrator account’s SPN and extracted the associated ticket hash

  8. Cracked the associated ticket hash offline, discovering the password Ticketmast1968

  9. Validated Administrator credentials and obtained domain administrator privileges

After initial enumeration with Nmap, the target appeared to be a Windows Active Directory Domain Controller based on the presence of Kerberos (88), LDAP (389), DNS 53, SMB (445), and Global Catalog Services (3268). SMB was selected as the initial attack path because file shares in Active Directory environments frequently contain configuration files, logon scripts, and other useful artifacts.

Anonymous access was tested against all shares, and it was found that the Replication share allowed read access for anonymous users. Upon accessing the Replication share, the file Groups.xml was identified. Groups.xml was a GPP credential file which contained an encrypted cpassword value associated with the SVC_TGS account.

Attack Path Analysis#

The Replication share exposed a GPP credential file containing a cpassword value associated with the SCV_TGS account. Although the password was encrypted, Microsoft publicly documented the encryption key used by GPP. Because of this, the password was easily decrypted. Successful recovery of the account credentials would provide authenticated domain access and create opportunities for further Active Directory enumeration and privilege escalation.

Initial Access#

Vulnerability Details#

Description: Anonymous Read Access to SMB Share, Group Policy Preferences (GPP) Credential Exposure

Vulnerability Classification: CWE-276: Incorrect Default Permissions, CWE-862: Missing Authorization, CWE-200: Exposure of Sensitive Information to an Unauthorized Actor

CVSS Score(s): N/A

MITRE ATT&CK: T1039 - Data from Network Shared Drive - Collection, T1552.006 - Unsecured Credentials: Group Policy Preferences - Credential Access

Anonymous access to the Replication share exposed a GPP credential file containing a cpassword value associated with a domain account. Because GPP passwords are recoverable using Microsoft’s publicly documented encryption key, the credentials could be extracted and used to obtain authenticated domain access.

Exploitation Steps#

  1. Connect to the SMB Replication share using SMBClient with anonymous access

  2. Download the groups.xml file

  3. Use GPP-decrypt to decrypt the password

  4. Log in to the SMB Users share to validate credentials

Key Commands / Payloads#

# Connect to Replication share
smbclient -N //10.129.83.82/Replication

# download Groups.xml file
get "active.htb\Policies\{31B2F340-016D-11D2-945F-00C04FB984F9}\MACHINE\Preferences\Groups\Groups.xml"

Privilege Escalation#

Vulnerability Details#

Description: Kerberoastable Service Account Protected by a Weak Password, Over Permissioned Service Account

Vulnerability Classification: CWE-521: Weak Password Requirements, CWE-269: Improper Privilege Management, CWE-272: Least Privilege Violation

CVSS Score: N/A

MITRE ATT&CK: T1558.003 - Kerberoasting - Credential Access, T1078.002 - Valid Accounts: Domain Accounts - Privilege Escalation

Following initial access, Active Directory accounts were enumerated to identify privileged users with registered SPNs. Enumeration revealed that the Administrator account was configured with a registered SPN, making it a viable Kerberoasting target. Because authenticated domain users can request Kerberos service tickets for accounts with registered SPNs, a TGS ticket was obtained and the associated hash extracted for offline password cracking. Successful recovery of the account password allowed authentication as the Administrator account, resulting in full compromise of the Active Directory domain. Note: flags documented in Appendix B

Privilege Escalation Steps#

  1. Enumerate all Users with SPNs to identify Kerberoastable targets

  2. Identify account Administrator as a Kerberoastable target with Domain Administrator privileges

  3. Request a TGS ticket and extract hash

  4. Perform offline cracking of extracted hash

  5. Validate cracked credentials

Key Commands / Payloads#

# Enumerate Kerberoastable accounts
ldapsearch -x -H ldap://10.129.83.82 -D SVC_TGS@active.htb -w GPPstillStandingStrong2k18 -b "dc=active,dc=htb" "(&(objectclass=user)(servicePrincipalName=*))" samaccountname ServicePrincipalname memberof

# Request TGS ticket and extract hash
impacket-GetUserSPNs active.htb/SVC_TGS:GPPstillStandingStrong2k18 -request-user Administrator -dc-ip 10.129.83.82 -output hash.txt

# Crack hash
hashcat -m 13100 -a 0 hash.txt /usr/share/wordlists/rockyou.txt 

# Connect to Users share to validate credentials
smbclient -u "Administrator"%Ticketmaster1968 //10.129.83.82/Users

Lessons Learned#

This was my first Active Directory focused machine. I was surprised by how approachable the attack path ultimately proved to be. Active Directory machines are often discussed as being notably more complex than traditional host-based machines, so I expected a much steeper learning curve. While the overall attack chain was longer than those found in the previous standalone machines I have completed, none of the individual steps were particularly difficult. What I enjoyed most about this machine was the realism of the attack path. The vulnerabilities leveraged during exploitation were the types of misconfigurations and weaknesses that could realistically be encountered in a production environment. Rather than relying on contrived hints or artificially placed clues to guide the attacker, each stage of the compromise followed a logical path of enumeration and the discovery of a genuine weakness within the environment. Some key takeaways include:

  • Multiple low-severity vulnerabilities can be just as dangerous as a single critical vulnerability when properly combined into a coherent attack path

  • Thorough enumeration is critical to successful exploitation of any machine, and becomes increasingly more important in an Active Directory environment

  • Temporary workarounds and convenience driven configuration changes often persist far longer than intended, creating opportunities for attackers
